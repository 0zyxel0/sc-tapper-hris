# Kiosk & Frontend Setup Guide

This guide explains how to initialize the backend accounts, what credentials to use for the frontend Guardhouse/Kiosk terminals, and how to configure them for operation.

---

## 1. Initializing the Kiosk Accounts

Before logging into the frontend, the backend must generate the pre-configured operational accounts and open default gate sessions. You do not need to create these manually in the Strapi Admin Panel.

### Option A: Automated Docker Setup (Recommended)
Ensure your `docker-compose.yml` has the auto-seed flag enabled for the Strapi service. This runs automatically on container start.
```yaml
environment:
  - AUTO_SEED=true
```

### Option B: Manual API Trigger
If running locally without Docker (e.g., `npm run develop`), trigger the setup manually:
```bash
# Bash / Linux / macOS:
curl -X POST http://localhost:1337/api/setup/seed

# Windows PowerShell:
Invoke-RestMethod -Uri "http://localhost:1337/api/setup/seed" -Method POST
```

To verify the setup status:
```bash
curl http://localhost:1337/api/setup/status
```

## 3. Frontend Configuration & Setup

To ensure the frontend correctly communicates with the open sessions generated by the backend, configure the environment on each specific kiosk device.

### Step 1: Frontend Environment Variables
On the physical kiosk running the Nuxt application (`sc-tapper-hris-web`), configure the `.env` file (or equivalent deployment config):

```env
# URL pointing to the Strapi backend instance
NUXT_PUBLIC_API_URL="http://127.0.0.1:1337"

# Hardware Device identifier assigned to this specific physical gate terminal
NUXT_PUBLIC_DEVICE_ID="GATE-01"
```

* For the **Main Gate**, set `NUXT_PUBLIC_DEVICE_ID="GATE-01"`.
* For the **Back Gate**, set `NUXT_PUBLIC_DEVICE_ID="GATE-02"`.
* For the **Warehouse**, set `NUXT_PUBLIC_DEVICE_ID="GATE-03"`.

### Step 2: Frontend Operator Login
1. Open the Nuxt frontend application in your browser or fullscreen Chromium kiosk wrapper (e.g., `http://localhost:3000/login`).
2. Enter the identifier and password corresponding to the gate device:
   * **Identifier:** `gate-01` (or `gate01@sc-tapper.local`)
   * **Password:** `Password123!`
3. Click **Sign In**. The frontend authenticates via `POST /api/auth/local` and securely stores the JWT session token.

### Step 3: Automated Session Discovery
Because the setup seed script automatically provisions an active attendance session for `GATE-01`, `GATE-02`, and `GATE-03` for the current date:
1. Upon login, the frontend will automatically execute:
   ```http
   GET /api/attendance/sessions/current?deviceId=GATE-01
   ```
2. The backend responds with the active session (`status: "Open"`).
3. The kiosk terminal skips the manual "Start Shift" modal and immediately transitions to the **"Ready to Scan"** fullscreen scanning loop.

## 4. Hardware Scanner Integration & Verification

1. Connect the USB RFID Scanner to the terminal. Most RFID scanners emulate a standard USB HID Keyboard.
2. Ensure the kiosk window has focus.
3. Tap an RFID card against the reader.
   * If testing with seeded mock data (via `POST /api/testing/seed`):
     * Tap or type UID: `111111` (John Doe - Active)
     * Tap or type UID: `222222` (Jane Smith - Active)
4. The scanner reads the card UID, enters `Enter`, and the frontend submits the scan to:
   ```http
   POST /api/attendance/scan
   Content-Type: application/json
   Authorization: Bearer <TOKEN>

   {
     "rfidUid": "111111",
     "deviceId": "GATE-01"
   }
   ```
5. The backend validates the card, verifies active employment, calculates the punch direction (`IN` or `OUT`), and logs the event against the current `GATE-01` session.
6. The terminal UI displays the confirmation overlay with the employee's name, photo, and attendance status.

## 5. Troubleshooting & FAQ

### 1. Login fails with `401 Unauthorized` or `Invalid identifier or password`
* Run `curl http://localhost:1337/api/setup/status` to ensure seeded users exist.
* If users have not been provisioned yet, call `POST /api/setup/seed`.
* Remember that the default password is case-sensitive: `Password123!`.

### 2. Frontend says "No Active Session"
* The default seeded sessions are created with the date of when the seeder was run. If midnight has passed or a session was previously closed, guards can click **"Open Session"** on the UI to initiate a new session for the day, or re-run the seed script.

### 3. Hardware RFID Scanner does not register
* Open a text editor (Notepad) on the kiosk machine and scan a card to ensure the hardware is functioning and outputting digits followed by a newline/Enter key.
